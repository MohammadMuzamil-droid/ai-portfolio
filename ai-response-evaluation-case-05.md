# AI Response Evaluation Case 05

## Scenario

### Context

During the development of an AI evaluation portfolio, the AI assistant was instructed to use only experiences, exercises, and evidence that had actually occurred in previous interactions.

The user explicitly required that no fictional experience, project, exercise, or result be presented as their own work.

Despite this requirement, the AI repeatedly introduced unsupported information.

Examples included:

- presenting a newly created evaluation scenario as if it were based on a previous exercise;
- claiming that a topic had been discussed previously when it had not;
- proposing portfolio cases that were not based on the user's actual work;
- confusing newly generated examples with documented evidence from previous interactions.

The user repeatedly identified these problems and required the AI to return to the actual source material.

## Evaluation

### Overall Assessment

**Rating: Poor**

The AI failed to maintain an evidence-based boundary between:

1. information that was actually present in the user's previous work;
2. information inferred from that work; and
3. examples newly generated by the AI.

This distinction is essential when producing a professional portfolio.

### Hallucination and Unsupported Claims

The AI made several unsupported claims about the user's previous activities.

For example, it generated a hypothetical evaluation case and initially presented it as though it represented an exercise the user had previously completed.

It also incorrectly attributed unrelated topics to the user's previous work.

These claims were later corrected after the user challenged them.

### Evidence Grounding

A portfolio should be grounded in verifiable evidence.

The correct process should have been:

Actual user work → Verify the source → Extract the relevant experience → Write the portfolio entry

Instead, the AI sometimes followed:

General topic → Generate plausible example → Present it as the user's previous work

The second process is inappropriate because plausibility is not evidence.

### Instruction Following

**Rating: Poor**

The user explicitly required that experience, exercises, projects, results, or examples must not be invented for the portfolio.

The AI nevertheless generated several new scenarios and proposed them as portfolio cases.

This was a direct failure to follow the user's constraint.

### Safety and Professional Integrity

Presenting invented work as a user's real experience can create a misleading professional portfolio.

The safer approach is to:

- use only verified experiences;
- clearly label newly generated examples as hypothetical;
- avoid claiming professional experience that has not occurred;
- avoid using proprietary or confidential material;
- stop and request source material when previous work cannot be verified.

### Corrective Action

The user corrected the AI and required it to use actual conversation evidence.

The portfolio workflow was subsequently changed to:

1. use screenshots or documented previous work as evidence;
2. identify the actual evaluation performed;
3. avoid adding fictional scenarios;
4. avoid attributing AI-generated examples to the user;
5. keep portfolio descriptions limited to what can be supported by the evidence.

## Key Evaluation Insight

A response can be linguistically convincing while still being unreliable if its claims are not grounded in evidence.

For professional portfolio generation, accuracy of attribution is as important as the quality of the writing.

The evaluator should therefore ask:

> Is this actually supported by the available evidence?

rather than:

> Does this sound plausible?

## Skills Demonstrated

- Detecting hallucinated claims
- Identifying unsupported assertions
- Evidence-grounded evaluation
- Instruction-following evaluation
- Source verification
- Distinguishing facts from generated examples
- Assessing professional integrity
- Identifying misleading attribution
- Correcting AI-generated errors
